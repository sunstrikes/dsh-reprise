# 05: 预算账本 —— 预扣、结算与 pause

**What to build:** 花销的闸。派发作业时按上限预扣，完成时按实际结算并退回差额；剩余预算在任何 tick 里都是确定值，因此判停可以真在 tick 里算。软限只停新派发，硬限进暂停而不是结束——钱花完不等于实验结束。

**Status:** resolved

- [x] 剩余预算在 tick 内是确定值，不依赖任何外部回调或异步对账。

## 结论

`packages/core/lib/budget.js`，全套 67/67（本票 11 条）。`loop.js` 里关于预算的分支全部搬空，只剩「问一个问题、照一个答案走」。

### 收口：一个判决函数，四种结论

`evaluate()` 返回 `ok | soft | hard | runtime`。**hard 与 runtime 是两个 verdict 而不是一个**：一个是钱花完了，一个是时间用完了，事后追问「这次为什么停」时这两个答案完全不同。两者都走 `pause`，都不走 `FINALIZE`。

`canDispatch()` 只在 soft/hard 说 no。软限之所以不能杀在途候选，是因为那笔钱已经花了——杀掉等于把已花的钱变成零收益。

### 谁能恢复暂停，这是本票真正新增的语义

之前只有「设一个 paused 字段」。现在有两条规则，且不可混淆：

| 暂停来源 | 谁能解除 |
|---|---|
| 自动（预算/时间耗尽） | 代码，在原因消失后的下一个 tick 自动解除——**加钱不需要重启** |
| 人工 | 只有人（`resume({force:true})`） |

代码不能撤销人的暂停，否则操作者按下的那个暂停会自己消失，而那是他唯一会记住的暂停。测试里专门有一条 `autoResumeIfClear` 对人工暂停返回 `not_applicable`。

### 一处照抄的陷阱被避开了

`started_at_ms` 只在工作区记录**第一次**出现时写入，而预算**不**写进工作区记录。原因来自票 11 的测绘结论：旧实现的状态快照里有一批字段，注释都声称「可热调不需重建」，但代码里根本没有 config→state 的回写路径，事实上 init 即冻结。如果这里把 config 的预算抄进工作区状态，就复制了同一个分裂——只不过方向反过来：配置改了但工作区里的旧值一直赢。

现在的语义是：**工作区只在被显式写入时才覆盖 config**（那正是人为加预算的动作），否则 config 说了算。

### `cost_*` 没有被搬过来（故意的）

前身仓库里有一组 `cost_*` 模块，字面像预算，实际是「把模型推理成本当成一个优化目标维度，与 AUC 做帕累托」。把它当预算搬过来，会让预算闸开始优化 AUC。本票只认 `budget`，不认 `cost`。
